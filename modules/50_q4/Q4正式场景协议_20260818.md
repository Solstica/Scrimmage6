# Q4 正式场景协议（formal_joint_v1）

本协议固定场景参数后再运行，不根据运行结果反向调整参数。每个场景都调用同一份全域 workload--energy--storage 联合模型，允许任务区域/开工时刻、BESS 和 Grid 同时优化，并重新执行完整域定价。

## 场景

| 类别 | 场景 ID | 参数 |
|---|---|---|
| Carbon | `carbon_100/75/50/25` | canonical 碳锚点的 100%、75%、50%、25% |
| Price | `price_attachment` | 附件逐时价格 |
| Price | `price_flat` | 各区域逐时价格替换为该区域附件均值 |
| Price | `price_peak_valley` | 每区域价格上四分位点乘 1.25，下四分位点乘 0.75，中间保持不变 |
| Renewable | `renew_nominal` | 附件名义新能源 |
| Renewable | `renew_down_80` | 全部区域、全部时刻乘 0.80 |
| Renewable | `renew_up_120` | 全部区域、全部时刻乘 1.20 |

canonical 碳锚点经核验为 `0.0 tCO2`，所以原始 Carbon 约束不活跃；正式论文中应明确这一事实，不得伪造减排曲线。若需要激活碳约束，必须另行冻结透明的压力协议，并标注为压力场景。

## 统一输出

每个场景输出 Cost、Carbon、Total/Mean/P95/Max Wait、Total/Mean/P95/Max Latency、RenewableUtilization、regional/system PeakNetImport、迁移任务数和任务覆盖数。输出状态必须保留 `FINISHED`、`DRAFT` 或 `NEEDS_REVIEW`，不能把 restricted-pool MIP gap 写成全局整数最优。

## 运行方式

先检查协议：

```powershell
D:\python3.12.7\python.exe modules\50_q4\code\q4_formal_scenarios.py --list
```

单个场景运行示例：

```powershell
D:\python3.12.7\python.exe modules\50_q4\code\q4_formal_scenarios.py --run --scenario-id price_flat --max-hours 8.5
```

每个场景写入 `results/formal_scenarios/<场景ID>/`，汇总六指标写入 `q4_formal_six_metrics.csv`。正式场景全部完成、accounting 统一并通过硬约束审计后，才能生成图 F 并把 Q4 从 `FINISHED_DRAFT` 升级为 `FROZEN + CHECKED`。
