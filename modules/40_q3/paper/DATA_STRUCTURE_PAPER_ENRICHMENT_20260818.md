# Q3 数据结构驱动论文强化要求（2026-08-18）

## 0. 目的

Q3 的数学模型已经很稳定，本轮不再加目标、不再换 LP/MILP。重点是把“为什么六区会自然出现三种储能角色”从文字结论升级为数据证据，并让 B0/E0/E1 的比较真正体现附件数据被开采后的机制发现。

正式主线：

`固定设施负荷 -> 新能源盈余结构 H -> H + SellLimit 三类角色 -> 统一两阶段 LP -> B0/E0/E1 -> 储能机制验证`。

---

## 1. 必须保留的数据关系

### R1 固定设施负荷下新能源极为充足

按 `L=PUE*(BaselineAI+NonAI)`：
- A: AvailableRenewable / Load ≈ 1.756；
- B: ≈ 1.775；
- C: ≈ 1.745；
- D: ≈ 1.770；
- E: ≈ 1.812；
- F: ≈ 1.782。

A--E 全 2407 h `H=AvailableRenewable-L >= 0`；F 仅 1 h `H<0`。

**模型作用：**说明 Q3 不是典型“新能源短缺下储能保供”问题，而是“新能源总体富余下的时序价值转移”问题。

### R2 SellLimit 把相同盈余状态切成不同经济角色

A/B/C：SellLimit=0；D/E/F：允许售电。

**模型作用：**与 H 共同导出三类角色：
- A/B/C：持续盈余 + 不可售；
- D/E：持续盈余 + 可售；
- F：盈余为主 + 单次短缺 + 可售。

该分类不是预设 cluster，不使用分类算法；是附件参数直接导致的机制划分。

### R3 附件 baseline 不是 Q3 终端 SOC 约束下完全可比的可行优化点

D/E/F baseline `SOC(2406)<InitialSOC`；RegionE Hour 0 另有约 1 MWh raw baseline 不一致。

**模型作用：**必须设置 E0 no-storage 同口径 benchmark，`E1-E0` 才能解释为 BESS 增量价值；不能把 B0-E1 全部归功于储能。

### R4 价格/碳/新能源存在关系，但当前 GridPurchase 基本退化

0--2399 h 各区时间关系近似：
- corr(Price, CarbonIntensity) ≈ -0.378；
- corr(CarbonIntensity, AvailableRenewable) ≈ -0.663；
- corr(Price, AvailableRenewable) ≈ -0.154。

**模型作用：**如果系统大量购电，本可出现低价与低碳冲突；但附件新能源极充足使 E0/E1 购电几乎降为 0，因此 Q3 没必要人为构造 Cost--Carbon 权重多目标。

### R5 同一统一 LP 自然产生三类最优行为

正式结果：
- A/B/C：Stage 2 零储能动作；
- D/E：储能低价期用新能源充电，高价值时段放电供负荷，释放同期新能源售电；
- F：除价值时移外，还覆盖唯一短缺小时的购电替代。

**论文作用：**这是“数据结构预测机制 -> LP 输出验证机制”的完整闭环，应作为 Q3 的主要亮点。

### R6 Stage 1 多重最优与 SCD 是求解表示问题，不是新的物理机制

**模型作用：**Cost -> Throughput 只用于从成本最优面选择物理清晰代表解；不要再展示某个 Stage 1 退化解的固定 SCD 数量/吞吐量。

## 2. 正文必须补强的 Data-to-Model 逻辑

### 2.1 在模型建立前先给“数据结构探针”

必须先让读者看到：

`H 的符号 + SellLimit -> 三类角色`，再进入统一 LP。

不要先写八变量 LP，再在结果中事后解释 A/B/C、D/E、F。

### 2.2 明确“储能价值”有两个来源

D/E/F：跨时段售电机会价值；
F：额外有短缺小时购电替代价值。

但不能写“F最高完全因为短缺小时”，因为容量、效率、价格结构也共同决定最终价值。

### 2.3 B0/E0/E1 的识别逻辑必须图文化

- B0：附件给定运行状态；
- E0：同负荷、同能源自由度、禁用 BESS；
- E1：完整 BESS。

必须让读者直接看到：

`E1-E0 = BESS incremental value`。

## 5. 写作验收

读者在进入 LP 公式前，应能回答：
1. 为什么 A/B/C 不需要储能；
2. 为什么 D/E 仍有储能价值；
3. 为什么 F 机制与 D/E 不完全相同；
4. 为什么 B0 不能直接用于量化储能贡献；
5. 为什么采用 Cost -> Throughput，而不是 Cost/Carbon/Peak/Fluctuation 加权和。

若这些答案只能从求解结果倒推，而不是由附件数据在建模前推出，本轮不算通过。
