## 已确定的数据与模型判断

- [x] Q1 不是 SFETA/REPTA 优化问题；它是“统计预测 + 基础调度机制”。
- [x] Q1-A 是 24 h 短期预测基线/参考模型，不承担长期负荷预测；不为 98 天历史引入长期趋势、概念漂移或复杂动态状态。
- [x] 1 h × 0--2399 只有约 2400 个时间观测，不属于高频长历史时序；复杂 LSTM/DGLM/季节模型没有数据依据时不启用。
- [x] 小时总任务到达近 Poisson：均值约 20.8333、Fano≈0.9687，lag 1/24/168 自相关很弱。
- [x] TaskType×SourceRegion 存在明显结构关系（Cramér's V≈0.434），因此 `(Region,TaskType)` 使用联合标记 `pi_rk`，不拆成独立 `P(R)P(K)`。
- [x] `GPU_Demand ⟂ SourceRegion | TaskType` 初步成立：三类 GPU×Region 检验 p 约 0.535/0.776/0.146，区域解释方差 η² < 0.001；GPU mark 主要按 TaskType 建模。
- [x] `Duration ⟂ SourceRegion | TaskType` 初步成立：三类 Kruskal-Wallis p 约 0.329/0.790/0.142，η² < 0.0005；不需要再按 Region 细分 Duration。
- [x] 主任务资源 mark 优先保留 `(GPU,Duration)|TaskType` 联合经验分布；主 GPU demand 使用其 GPU 边际，GPU-hour 使用联合 mark，避免把“相关近 0”误写成严格独立。
- [x] 离散均匀 GPU/Duration 只作简化对照，不作为唯一真实分布假设。
- [x] Gamma-Poisson / Dirichlet Bayesian 更新不作为主模型必需部分；当前样本量下频率估计足够作为主实现。
- [x] 预测对象锁定为“每小时新到达任务的 GPU_Demand 总量”；GPU-hour 是工作量补充，运行中 GPU utilization 由 Q1-B 状态演化得到。
