# CUMCM 论文版式与写作骨架规范

本文件记录团队已经在上一场完整论文中实际调通的公共版式和章节组织。目标是：**下一场比赛直接在现成格式上删改内容，不再重新调字体、标题、图表、公式、伪代码和分页。**

公共格式只在 `feature/paper-shell` 修改；各章节只编辑自己的 `modules/.../paper/*.tex`。

## 1. 默认全文结构

模板直接编译 `paper/main.tex` 时应看到：

1. 第1页：论文标题 + 摘要；
2. 第2页：目录（可关闭）；
3. 正文从“问题重述”开始重新计第1页；
4. 符号说明；
5. 模型假设；
6. 问题一完整示例；
7. 问题二、问题三只保留一级章节标题；
8. 模型总结与评价；
9. 参考文献另起一页；
10. 附录另起一页；
11. AI使用报告另起一页。

目录开关在 `paper/settings.tex`：

```tex
\showtoctrue   % 显示目录
% \showtocfalse % 隐藏目录
```

不要在章节文件中自行加 `\clearpage` 处理全文分页；公共分页统一由 `paper/main.tex` 管理。

## 2. 字体、页面和正文

当前模板复用上一场正式稿的主要排版口径：

- 纸张：A4；
- 页边距：上、下、左、右均 `25 mm`；
- 正文中文：Windows 优先宋体 `SimSun`，无该字体时回退到 Fandol；
- 正文英文和数字：Windows 优先 Times New Roman，无该字体时回退到 TeX Gyre Termes；
- 正文基准字号：小四；
- 行距：`\baselinestretch = 1.38`；
- 段首缩进：`2em`；
- 段间距：0，不额外空行制造视觉间距。

不要把字体设置散落进章节文件。需要改字体、页边距、标题字号、行距时，只改 `paper/preamble.tex`。

## 3. 标题层级

采用上一场论文的层级：

- 论文题目：三号、加粗、居中；
- 一级标题：中文序号，例如 `一、问题重述`，居中、加粗；
- 二级标题：`4.1` 形式，左对齐、加粗；
- 三级标题：`4.1.1` 形式，左对齐、加粗；
- 目录显示到二级标题。

章节标题不要手打序号，统一使用 `\section`、`\subsection`、`\subsubsection`。

## 4. 摘要

摘要采用团队长期使用的功能结构：

- 总述：1段，约2--3行；
- 每个问题：先按“任务--准备--模型--算法--结果--解释”六个功能句构思，再压缩为约4--6行；
- 末段“本文特点”：最多突出2个真正贯穿全文的亮点；
- 关键词：一般4--6个，按“对象/模型/算法/关键机制”的顺序选择。

问题标签和关键结果可加粗，例如：

```tex
\textbf{针对问题一，}建立\textbf{某模型}……得到\textbf{关键结果}。
```

模板摘要只保留“总述 + 问题一 + 本文特点 + 关键词”四块，用于展示最终版式，问题二、三的示例文字故意删除，避免下次误把旧题内容当模板内容。

## 5. 每问建议结构

不是每问机械套八个标题，但通常按以下顺序组织：

```text
问题描述与分析
→ 总体流程图
→ 必要的预备工作 / 数据处理
→ 模型建立
→ 模型汇总
→ 模型求解
→ 结果与分析
→ 针对本问主要不确定性的检验
```

优化模型要明确：决策变量、目标函数、约束和模型汇总。解析推导/直接计算问题不必为了形式强行构造优化模型。

## 6. 公式

- 普通定义和不重要公式优先写成行内公式；
- 承担模型定义、核心推导、约束、结果的公式再使用独立编号；
- 统一使用 `\label{eq:...}` + `\eqref{eq:...}`，不要手打“公式(3)”；
- 向量、矩阵统一用粗体，例如 `\boldsymbol\theta`、`\mathbf A`；
- 单位用正体，例如 `\mathrm{kg}`、`\mathrm{cm}^{-1}`；
- 复杂模型建立后建议增加“模型汇总”，把输入、核心关系、目标和约束集中写成一组公式；
- 不把几十行连续推导堆在正文中，只有决定模型结构的步骤保留。

问题一示例已经包含：观测方程、目标函数、有界优化和模型汇总，可直接照格式替换。

## 7. 表格

统一使用三线表，不画纵向网格线。建议样式：

```tex
\begin{table}[!htbp]
\centering
\caption{表题}
\label{tab:xxx}
\begin{tabular}{cccc}
\toprule
\rowcolor{CumcmLightBlue}
列1 & 列2 & 列3 & 列4 \\
\midrule
... \\
\bottomrule
\end{tabular}
\end{table}
```

规范：

- 表题由LaTeX统一生成，不在图片里写；
- 表头可用 `CumcmLightBlue` 浅蓝底；
- 单位尽量放在表头或变量定义中；
- 小数位必须与数据精度和论文结论一致；
- 一张表只承担一个信息任务，避免塞入过多无关参数。

符号表固定使用 `tabularx`，模板已给示例。

## 8. 插图与 Origin 图规范

所有正文图放在对应模块：

```text
modules/<模块>/figures/
```

Origin、Excel、AGX 等可编辑源放：

```text
modules/<模块>/figures/editable/
```

不要把可编辑图源散落在根目录，也不要只保留导出的PNG而丢失Origin/Excel工程。

上一场最终统一的论文视觉尺寸：

- 单个Origin小图：`0.44\textwidth`；
- 两个独立小图并排：每个约 `0.44\textwidth`，总宽约 `0.88\textwidth`；
- 已在Origin中合成的双面板图：整张 `0.88\textwidth`，**不要再按0.44缩小**；
- 总体流程图：约 `1.0\textwidth`；
- 机理示意图：通常 `0.70\textwidth`，复杂时可放宽到 `0.88\textwidth`。

模板已定义宏：

```tex
\FigureSingleWidth
\FigureDoubleWidth
\FigureFlowWidth
\FigureMechanismWidth
```

优先使用这些宏，不在各章节随意写 0.53、0.67 等临时宽度。

图形本体的规范：

- 图中不要再写与LaTeX图题重复的大标题；
- 坐标轴、单位、图例在同组图中字号一致；
- 同类图保持相同物理尺寸；
- 颜色用于区分信息，不追求花哨；
- 图题必须说明“画了什么”，正文紧接着解释“说明了什么”；
- 图若对应正式结果，数据必须来自当前活动代码/表格，不从截图或旧稿手录。

问题一模板用TikZ展示了流程图和两个并排小图的尺寸。实际比赛可以替换成Origin/PDF/PNG，不需要保留示例图形。

## 9. 伪代码

伪代码使用 `algorithm2e`，上一场正式稿采用：

- ruled + lined + 行号；
- Input / Initialize / Output；
- 关键循环、条件判断和可行性检查完整保留；
- 行距约0.92；
- 不直接复制Python语法；
- 伪代码解释“算法机制”，代码文件负责“实现细节”。

标准入口示例：

```text
modules/20_q1/paper/q1_algorithm.tex
```

若某问是纯解析推导或直接计算，没有必要强行写伪代码。

## 10. 代码附录

正文附录优先列“文件 + 功能”，再根据需要放1个短代码片段展示排版；完整程序保留在仓库中。不要把几十页代码复制进论文。

代码使用 `listings`：灰色浅底、细边框、左侧行号、自动换行。模板附录已有可直接替换的示例。

## 11. 模型评价

保留四块：

```text
模型总结
模型优点
模型局限
改进方向
```

每一点必须针对本文实际处理，不写“模型具有较高精度、适用范围广”等无法由结果支撑的套话。

## 12. 参考文献

- 正式论文建议至少10篇，英文文献不少于3篇；
- 新方法、材料参数、数据来源优先引用原始论文/官方资料；
- 不用往届竞赛论文替代科学来源；
- 引用必须真正支持对应句子；
- 三人以上作者按比赛/学校最终格式统一处理；
- 参考文献另起一页。

模板只放3条真实的格式示例，开赛后应替换/扩充。

## 13. 附录与 AI 使用报告

参考文献、附录、AI使用报告均由 `paper/main.tex` 强制另起一页。

附录只在目录中保留一级“附录：程序及结果文件说明”，内部不要再用有编号的 `\subsection` 导致出现类似“7.5 程序清单”的错误目录项。

AI使用报告只说明：AI参与了哪些环节、团队如何复核、正式结果从哪里计算得到。不要写“与范文差多少”“没有为了贴合答案”等内部答辩式语言。

## 14. 修改格式前的责任边界

- 字体、页边距、标题、目录、图表宏、公共宏包：`feature/paper-shell`；
- 摘要：`feature/abstract`；
- 问题重述：`feature/restatement`；
- 符号说明：`feature/notation`；
- 模型假设：`feature/assumptions`；
- Q1/Q2/Q3/Q4：各自分支；
- 模型评价、参考文献、附录、AI报告：各自独立分支。

AI若认为“整个论文格式需要调整”，必须先说明应改 `paper-shell`，不能在Q1/Q2章节里偷偷重定义字体或标题。

## 15. 开赛后最小改法

模板不是让大家从空白开始，而是：

1. 改 `paper/title.tex` 的标题；
2. 按题目数运行 `scripts/set_questions.py`；
3. 各章节直接替换示例文字；
4. Q1保留有用的小节、公式、表格、伪代码和图环境，删掉不适用部分；
5. Q2/Q3从一级标题开始补正文；
6. 图表按固定资源路径替换；
7. 不重新设计字体、行距和编号，除非比赛官方模板发生变化。
